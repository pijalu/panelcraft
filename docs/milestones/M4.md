## Decisions

- **D-M4-1 · Exporter lives in `web/src/engine/format/mermaidExport.ts`** (pure,
  FS enters via `resolveImport` callback; `workspace/io.exportMmd` wires the
  virtual FS in). The M3 structural exporter in `io.ts` is replaced; corpus
  goldens `testdata/corpus/<case>/export.mmd` regenerate via
  `npm run corpus:accept` (now also runs mermaidExport.test.ts with
  EXPORT_FIXTURE=1). Goldens are TS-only — the Go parity job replays parse
  goldens, it has no converters (documented corpus layout, M1 D-M1-23).
- **D-M4-2 · Declared drops (FR-M4/M5), fixed order**: title, theme, level,
  direction (auto-layout), flows, views (positions/layout),
  descriptions/technology, properties, unknown attributes, icons,
  note anchors (detach), style beyond fill (stroke/text/shape), waypoints,
  system vs container kind distinction (both export as rect), nested groups
  (group inside group), links with group endpoints,
  `import <alias> (<path>) unresolved`. Not dropped but *flattened*: imports
  (objects inlined under `alias_id`, `%% imported from <path>` marks, §9).
- **D-M4-3 · Groups emit first**: mermaid re-import keeps the first node
  definition, so group children must be created *inside* the subgraph block —
  otherwise `contains` is lost on round trip. Property test (lossless to the
  declared subset) runs over all 15 corpus canonicals; `system` objects
  re-import as `container` (declared §8 aliasing); link endpoints without an
  object statement re-import as implicit containers (same as §8 import).
- **D-M4-4 · S2 paste semantics**: pasting mermaid (`flowchart`/`graph`/C4)
  into the code view detects the dialect, converts to PDL (diagnostics
  surfaced in the problems panel), and the buffer becomes canonical PDL —
  the file remains a valid `.pcd` (FR-M6: no mermaid-validity requirement).
  SPEC S2's "file remains valid mermaid" is satisfied at paste-time (the
  snippet is valid mermaid on entry); the source of truth afterwards is PDL
  per FR-K5. Recorded for SPEC review in M7 (backlog candidate).
- **D-M4-5 · Conflict policy (sync machine)**: canvas changes queued while
  the buffer diverges are re-applied to the canvas AND re-rendered when the
  machine returns to clean (last canvas-relevant event wins; both sides
  converge to the same doc). After an apply, `divergedFromSaved` stays true
  until the consumer confirms the save (FR-K5: file = source of truth).
- **D-M4-6 · File persistence split**: a CODE apply writes the full
  canonical text to the file (`saveText`, FR-K5 — the canvas projection
  would drop flows/views/styles); a CANVAS structural edit keeps M3
  semantics and rewrites the file from the projection (`saveCanvas`) —
  code-only sections do not survive canvas-side structural edits (merging
  projections is deferred to M6 re-layout work).

  - S2 initially FAILED (buffer stuck at the pasted text; canvas additions
    never reached the code view). Two real bugs isolated with a wired hook
    test (RED before each fix):
    1. Apply-port ORDER: `ctrl.loadState` synchronously drives the M3
       `onCtrlState→saveCanvas` bridge, which wrote the canvas PROJECTION to
       the file AFTER `saveText` had written the full text — the file ended up
       as the projection, so the echo's `markSaved(canon(file))` recorded a
       text the buffer never had and `divergedFromSaved` stuck true.
       Fix: `saveText` runs AFTER `loadState` (full text wins, D-M4-6).
    2. Bridge parse round trip: canvas emissions were re-parsed via
       `parsePDL(stateToPcd(...))` before `canvasChanged`, but the projection
       can contain non-re-parsable text — pcdToState's synthesized link ids
       were `from->to`, and `>` is not an ident char (§1) — so genuine updates
       were silently DROPPED. Fix: `stateToDoc(state)` (exported from
       workspace.ts, `stateToPcd = printDoc(stateToDoc)`) feeds the machine
       directly; the synthesized fallback became `from-to-<i>` (valid ident,
       re-parses; FR-K2). `docToState` extracted for the apply port (no
       double parse).
  - Bridge also calls `markSaved(canon(file))` on the genuine-change path:
    the emission's saveCanvas already wrote the projection synchronously, so
    the chip must reflect it (else canvas edits that re-canonicalize
    ids/types showed a diverged false alarm).
  - `useCodeSync.test.tsx` upgraded: the controller double now mirrors the
    real wiring (loadState → onState → saveCanvas + snap rerender), which is
