## Design decisions

- **Dagre dependency**: pre-approved — ADR-0004 (dependency policy: dagre MIT,
  "hand-rolling Sugiyama = high-risk algorithm code") and ADR-0005 §3 (license
  gate: dagre MIT listed as approved). Pinned via lockfile (`dagre@0.8.x`,
  `@types/dagre` dev-only).
- **LayoutEngine port** (`engine/layout/ports.ts`): pure contract — nodes
  (id + size + optional pinnedAt), edges (from/to), options (dir). Adapter
  (`dagre.ts`) is the only dagre importer; tests inject the adapter, UI
  composes it (ARCHITECTURE.md port rule).
- **Determinism**: adapter stable-sorts nodes by id and edges by
  `(from,to)` before feeding dagre, dedupes parallel edges (first wins), and
  post-normalizes to canvas units (top-left origin, y down, FILE-FORMAT
  §7.2). Same input arrays in any order → same output map (unit test gate).
- **Pins (FR-V4)**: dagre has no fixed-node support; pinned nodes participate
  in the graph (so topology/rank structure stays sound) and their saved
  positions are hard-overwritten after `run()`. Un-pinned neighbors lay out
  around the pinned rank structure; possible overlap with a pin is accepted
  for v1 and noted here.
- **Apply-to-file** (`engine/layout/apply.ts`): explicit-commit pure function
  `applyLayoutToView(doc, viewName, positions)` — writes `position` lines
  into the named view (replacing existing lines for the same ids, others
  kept), sorted by id for canonical printing. Unknown ids are filtered.
  Never called automatically — canvas camera/layout stays session-local
  until the user commits (FILE-FORMAT §7.2).
- **Implicit default view**: a doc with zero `views` gets a created view
  named "Default" on first explicit layout commit (the implicit default view
  has no syntax representation; the commit needs a concrete view statement).
