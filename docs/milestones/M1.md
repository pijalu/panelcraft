## Decisions (binding; errata feed WP10 / FILE-FORMAT.md)

- **D-M1-1 IR JSON canonical form**: fixed key order (TS builders in
  `serialize.ts` ⇄ Go struct field order in `internal/ir/ir.go`); empty arrays
  omitted on both sides; `true`-only booleans (`bidir`, `flip`, `dashed`);
  2-space indent; trailing newline; Go encoder `SetEscapeHTML(false)` so
  `<`, `>`, `&` match `JSON.stringify` output.
- **D-M1-2 doc-level comments**: leading comments before the first meta
  directive serialize under the same `"comments"` key as statement comments.
- **D-M1-3 step union encoding**: flat object with `type` discriminator; keys
  `type, text, from, to, label, linkRef, flip, target, branches, lanes, file,
  flow, ret, comments, pos` — exactly one payload group set (Go: one struct,
  all `omitempty`).
- **D-M1-4 view positions**: `x`/`y` serialize as numbers (0 legal; Go uses
  `*float64` to survive `omitempty`).
- **D-M1-5 fuzzing without new deps**: WP3 property fuzz uses a hand-rolled
  seeded PRNG (deterministic, no `fast-check` dependency ⇒ no ADR needed).
- **D-M1-6 colors vs comments**: `#` + exactly 3/6 hex digits + delimiter lexes
  as COLOR; any other `#` starts a comment. `#` is otherwise unambiguous.
- **D-M1-7 syntax error codes** (abort the file): E100 unexpected, E101
  unterminated string, E102 invalid identifier, E103 bad/missing version,
  E104 unclosed block, E105 unknown top-level statement, E106 invalid escape,
  E107 stray `}` (reserved), E108 invalid arrow, E109 invalid number (reserved
  path), E110 duplicate block attribute, E111 invalid color, E112 nesting
  >32, E113 invalid goto target.
- **D-M1-8 identifiers**: charset `[a-zA-Z][a-zA-Z0-9_-]*` ≤64 (§1 said
  lowercase-only but §4 auto link ids are `L<n>` — uppercase first letter
  allowed; lowercase remains the convention). Overlong runs = E102.
- **D-M1-9 msg-step modifiers order-free**: `: "label"`, `as Ref`, `flip` may
  appear in any order (§14 example writes `as L3 : "label"`; §6 grammar said
  label-first — grammar is normative superset now).
- **D-M1-10 trailing same-line comments** attach to the FOLLOWING statement
  (lexer has no token-boundary lookahead; simple + deterministic).
- **D-M1-11 reversed arrows normalize**: `a <- b` / `a <-t-> b` store
  `from=b, to=a` (+type); canonical printer always prints `->`. `<->` keeps
  endpoints, sets `bidir: true`.
- **D-M1-12 comments inside blocks** accumulate and attach to the next parsed
  statement (possibly the next sibling after `}`); never dropped.
- **D-M1-13 goto target required** (§6 grammar's optional Target is a typo);
  quoted target must be `"path#flowId"`; `return end` is default (not stored).
- **D-M1-14 duplicate meta directives**: first wins, W100 warning (parse-level).
- **D-M1-15 tagged-id lists (tag/contains)** are line-scoped: members must sit
  on the same source line as the keyword (single-line blocks stay parseable).
- **D-M1-16 link ids are data**: the printer always emits `as <id>` when a
  link carries one (unref'd ids included) — lossless round-trip (§1.2) wins
  over §4's minimal-noise sketch. Same rule keeps flow `as id` and view
  `as id`. A msg step's arrow always prints `->` (flip is a modifier).
- **D-M1-17 empty collections vanish in IR JSON**: serializer wraps `tags`,
  `contains`, `waypoints` with the omit-empty helper (Go `omitempty` parity);
  printing drops them, so the canonical IR for empty is *absent*, not `[]`.
- **D-M1-18 semantic-rule refinements** (WP4, feed §10 errata): P104 covers
  both msg-step forms — without `as`, an undirected link pair must exist
  (either direction); with `as`, the referenced link id must exist. P106
  applies to any object with `attach` (notes are just the common case). P201
  is spec-literal (links + flow references only; `attach` does not count),
  so attached notes still warn — acceptable noise. P202 "visual" =
  msg/process/alt/par/goto (intro/info/conclusion don't count).
- **D-M1-19 `//` line comments**: lexer accepts `// …` like `# …` (same
  comment token, text stored without the slashes). Drivers: agents.md mandates
  the `// SPDX-License-Identifier: GPL-3.0-only` header on every source file,
  and the architecture seeds carry it; `/` has no other grammar use.
- **D-M1-20 exit-code policy (FR-X errata)**: exit 1 only for error-severity
  findings (E1xx aborts, P1xx errors); warnings (P2xx) and info (P204) do not
  affect the exit code. Otherwise the §10 severity split would be meaningless
  and every attached note (P201) would fail CI.
- **P205 unknown block attribute** = warning (§12 "kept as raw data, warning
  P2xx"); code assigned P205. File-level errata entry in WP10.

### M1-WP3 — canonical printer + printer fuzz (TS)
- `web/src/engine/format/printer.ts`: §11 canonical form — fixed section order
  (magic → meta → imports → objects → links → flows → views → styles), one
  attribute per line, 2-space indent, minimal quoting (escapes `\` and `"`),
  comments re-attached above their statement, blank line between sections;
  step dispatch table mirrors the parser's structure (complexity ≤12);
  link ids always emitted (D-M1-16).
- `web/src/engine/format/fuzz.ts`: mulberry32 seeded PRNG (`rngFrom`) +
  `forAllSeeds` (D-M1-5); failures report the reproducible seed.
- `web/src/engine/format/printer.test.ts`: checkout idempotence
  (print∘parse∘print = print) + IR stability modulo positions (compare via
  canonical serializer, deep-zeroed positions, name defaults to id), escape
  round-trip, §2 section ordering, and a 50-seed doc-generator fuzz (alt/par
  nesting, nasty strings incl. quotes/backslashes/`#`/unicode/empty).
- Found via fuzz + fixed: serializer emitted `"tags": []` / empty `waypoints`
  where Go `omitempty` omits → omit-empty alignment (D-M1-17); fixture
  regenerated (`CORPUS_FIXTURE=1`), Go parity re-verified byte-identical.
